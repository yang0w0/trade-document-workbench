# 本地网页应用

本目录是根项目中统一网页应用的源码，包含集装箱规划、FastAPI 服务和贸易单据提取页面。项目来源与许可信息统一见根目录 README。

## 本机运行

Windows 首次运行 `run_web_app.bat` 会创建 `web_env` 虚拟环境并安装 `requirements-server.txt` 中的依赖。需要 Python 3.11 或更高版本。随后启动网页服务，访问 `http://127.0.0.1:8000`。服务和 OCR 均在本机运行。

也可手动启动：

```powershell
python -m venv web_env
web_env\Scripts\python -m pip install -r requirements-server.txt
web_env\Scripts\python -m uvicorn server.main:app --host 127.0.0.1 --port 8000
```

贸易单据页面的“导入单据”悬浮按钮可拖动，位置自动保存在当前浏览器中，刷新或重新打开页面时恢复；窗口缩小时会限制在可见范围内。点击按钮打开独立导入弹窗，可选择多个文件、继续添加、逐个移除或清空后再识别。在网页任意区域拖入文件时，会先列出文件并询问是否导入；确认后打开导入弹窗，取消则保留现有文件。识别期间禁止更改文件列表，全部识别成功后自动关闭弹窗并显示字段汇总，失败时保留窗口供重试。此调整只涉及当前网页源码，不会更新旧便携 EXE。

## 主要目录

- `web/`：静态网页、集装箱页面及单据导入界面
- `server/`：FastAPI 接口、任务管理及单据解析/OCR
- `packer_pro.py`、`block_engine.py`：集装箱算法
- `requirements-server.txt`：本机网页服务和文档识别依赖

最大装填：数量留空或填 0，后端先保留定量货物，再搜索并补充剩余空间。网页使用标准计算的短预算自动搜索；产品底层优先级可在货物卡片中选填，留空不启用。结果标明停止原因，不将可行装载量伪称为已证明的全局最大值。

网页便携 EXE 的构建入口为 `../packaging/build-portable.ps1`，与本目录共用后端和网页。`build_exe.bat` 是旧命令行程序的构建脚本，不用于网页便携版。

上传文件由本机服务解析；录入中的当前方案保存在当前浏览器本地存储中，装箱商品模板、单据商品档案和集装箱模板保存在后端 `data/templates.json`（可用 `LOADER_TEMPLATE_FILE` 指定位置）。单据商品模板保留当前支持的十项产品字段，按保存值恢复，不自动推算缺失数量或金额。Docker 部署使用 `loader_data` 持久卷，重建容器后模板仍保留。当前识别规则为首版，后续应根据用户提供的格式样例校准。

贸易单据的产品列表按独立卡片录入，卡片右上角“保存模板”只保存该产品的十项字段，弹窗名称默认使用产品名；常用产品区只显示快捷按钮，每个模板右上角可删除。其他栏目通过“保存栏目模板”保存各自内容，页面顶部右侧“总体模板”保存全部栏目、自定义字段及产品列表。这些模板也保存在后端 `data/templates.json`；同种类同名保存可确认覆盖，套用栏目或总体模板前会提示替换填写内容，源文件和识别证据保留。贸易单据模板按保存内容恢复数量与金额，不自动计算；属于填写模板，不是正式单据的排版模板。新增种类需要重启源码服务后使用；旧便携 EXE 需重新构建才会包含改动。
