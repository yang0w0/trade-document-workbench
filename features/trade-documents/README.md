# 贸易单据模块

## 目标流程

1. 从网页导入合同、PI 或其他来源资料（预期包括 Excel、Word 和 PDF）。
2. 提取买方/卖方、合同/发票编号、产品描述、包装、数量、单价、金额、港口、重量和尺寸等实际存在的字段，并记录字段来源。
3. 在网页上展示识别值与来源，供用户核对；缺失或不确定的重量、尺寸等字段需要用户确认或由已确认的产品资料匹配，不得默默推算。
4. 用户选择需要生成的 INV、PL 等文件以及 Excel、Word 或 PDF 格式，按用户提供的模板填充并下载。
5. 用户确认的货物数据可通过[集装箱模块公开接口](../../docs/interfaces/container-planner-api.md)提交给装箱功能。

当前首版已在 `application/` 网页和 FastAPI 后端实现文件导入、字段候选识别、OCR、重复值合并/冲突展示、证据定位、人工修订与本地保存。字段别名和解析规则尚需结合用户后续提供的样例持续完善。按模板生成 INV/PL 仍需先取得并确认输出模板。

产品卡片、常用产品模板及字段汇总 Excel 的产品页按本地 9 份真实文件的跨文件出现情况，保留产品名称、规格型号、HS 编码、数量、单价、金额、币种、生产日期、样品数量、生产批号共 10 项，不以“是否为固定产品属性”划分。字段范围及来源数量见 [产品字段复用核对](tests/product-field-reuse.md)。适用于当前支持的合同、PI、发票及申报资料；输入仍按原有字段别名识别，并保留来源证据和冲突候选。历史模板应用时只读取这 10 项；原始识别结果和已有记录中的其他资料保留，不自动推断缺失值或重算识别金额。本次不扩展按产品逐行匹配及正式单据生成能力。

2026-10-17 已对本地 `真实数据/` 的全部 9 份资料逐份通过 HTTP 上传接口验收，覆盖 PDF、DOC、DOCX、XLS、XLSX。修复内容、字段适用范围和验证记录见 [识别验收记录](tests/recognition-verification.md)。资料原地读取，测试只保存文件哈希、字段名和结果，不保存原文或提取值。

旧版 DOC 在本机通过 LibreOffice 临时转换后读取；可通过 `LIBREOFFICE_PATH` 指定程序路径。OCR 在独立子进程执行，异常或超时不会退出网页服务；Windows 运行库已固定为实测可用的 `onnxruntime==1.20.1`。

Word/PDF 来源现在可点击，在新标签页按原页版式查看、定位和缩放，可下载导入原件。导入弹窗中的 Word/PDF 文件名也可直接打开预览。Word 依赖本机 Word 或 LibreOffice 排版；PDF 直接渲染原文件，扫描 PDF 按已有 OCR 区域高亮。预览会话在本机内存保留一小时，过期或服务重启需从来源重新打开。尚未取得输出模板，字段映射及生成修改文件能力保持关闭，扩展约定见记录接口。

实现位于 `application/server/document_sources.py`、`application/server/trade_documents.py`，以及 `application/web/document-source.html`、`application/web/js/document-source.js`、`application/web/css/document-source.css` 和来源按钮所在的 `application/web/js/trade-documents.js`。本轮无新增 Python/JS 依赖；旧便携 EXE 不随源码自动更新，后续打包需包含这些静态资源，并提供 Word 排版引擎。

## 模块边界

2026-10-19 补齐旧版 `.xls` 来源查看：与 `.xlsx` 共用工作簿页面，文件名和字段来源均可点击；支持按单元格或仅有行号的证据定位、工作表切换、合并区域、基本字体/颜色/边框/行列尺寸和原件下载。`.xls` 使用已有 xlrd 直接读取并只读展示，不要求用户转换格式，也不按文件名或模板适配；`.xlsx` 保留编辑。表格预览不显示嵌入图片、图表或打印分页，完整内容可下载原件查看。合成回归见 `test_workbook_source.py`、`test_workbook_navigation.cjs` 和 `test_field_controls.cjs`。用户指定 XLS 原地上传验收结果见 `xls-source-audit.json`：387 个单元格值一致，17 条单元格证据和 3 条行证据均可定位，下载原件字节一致且磁盘原件未变。未新增生产依赖，旧 EXE 未重新打包。

字段核对界面统一由 `application/web/js/trade-documents.js` 的 `makeFieldControl` 管理输入、自适应高度、候选点击填入、选中状态和来源展示。单据、交易方、产品、运输、付款、包装、自定义及动态字段均使用同一控件；产品适配层只处理逐产品存储、人工编辑标记和卡片标题。候选左侧点击填入，已填入候选保持白底并在左侧显示绿色勾号；来源存在多个不同候选且填写内容为空（含纯空格）时，仅在字段标签与所属左侧栏目入口的文字左侧显示一处红点，红点随标签垂直居中，产品页沿用相同布局，选择候选或手工填写非空内容后即时清除，清空后恢复。相同值的重复来源不触发冲突提醒，手动或模板创建的产品不显示来源冲突红点。最终填写内容为 14px 常规字重，下方候选为 12px 常规字重，字段标签为 12px 中等字重；仅右侧来源文字以 11.5px、650 字重突出。右侧来源入口使用 18px 无底块的亮蓝文件检索图标，仅展示首条来源中明确出现的字段名称，无法明确匹配时显示“查看来源”。鼠标悬浮候选或点击标记打开详情弹窗，键盘也可激活标记并用 Escape 关闭。弹窗内展示首条来源和置信度，其余来源保留在可展开列表中；文件名、位置标签及原文引用分层呈现，原文预览继续沿用现有适配接口。原文与位置不进入候选行，来源信息不占用主体填写区。

合成回归入口：`node features/trade-documents/tests/test_field_controls.cjs`，覆盖产品及普通字段候选填入、人工修改、保存、后续导入保留选择、重复来源折叠、不同候选共用位置、空证据回退及预览参数。此界面调整未改变 HTTP 契约或识别规则。

2026-10-19 填写模板：产品卡片右侧保存当前产品，命名弹窗默认产品名，常用产品仅显示可使用/删除的快捷按钮；保留原有十项产品字段。其余栏目支持独立模板，顶部右侧提供总体模板管理。所有模板沿用后端持久存储，同名覆盖、栏目/总体套用与删除均需确认；套用只替换填写内容，保留候选和来源证据。接口兼容增加 `trade_sections`、`trade_records`，详情见标准记录契约。合成验证：`node features/trade-documents/tests/test_template_actions.cjs` 与 `application/web_env/Scripts/python.exe features/trade-documents/tests/test_saved_templates.py`，不读取真实单据、不运行 OCR。

来源弹窗位置由同一控件统一计算：优先右侧，其次左侧，两侧不足时贴上方，上方也不足才贴下方，并保持在视口内。上下布局不留会暴露相邻候选的悬浮间隙，避免鼠标进入详情时切到下一候选；定位分支已纳入上述合成回归。

产品来源提示只用于识别自动建立的产品卡片。手动“添加产品”、常用产品模板和总体模板建立的产品不展示识别候选、来源标记、来源窗口或缺失来源说明；新增产品保持空白。点击填写框时，下拉列出上方产品同字段已填写的非空值并去重，点击即可填入和保存，不附带来源证据。下拉按打开时的最新填写值生成，支持 Tab、向下键进入选项和 Escape 关闭。恢复本机记录时保留识别产品标记和已修改字段，后续重新导入仍可核对来源并保留人工修改。此调整只涉及前端，不改变识别规则和 HTTP 接口；合成回归沿用 `test_field_controls.cjs`、`test_template_actions.cjs`、`test_product_import.cjs`。

本模块拥有单据上传、内容提取、字段证据、核对界面、字段映射和文件生成。网页全局布局和导航由 `web-app/` 负责，装箱算法和 3D 结果由 `features/container-planner/` 负责。

2026-10-19 字段标签调色板：全部字段名称支持点击或键盘激活选色，提供十种常用色、自定义颜色及清除颜色。默认无底色；按标签名称在当前浏览器保存，同名字段同步显示，深色底自动使用白字。颜色偏好独立于核对记录，不进入模板或 HTTP 契约。实现位于 `application/web/js/trade-documents.js` 与 `application/web/css/app.css`；合成验证为 `node features/trade-documents/tests/test_field_colors.cjs`。仅修改网页静态资源，旧便携 EXE 不随源码自动更新。
