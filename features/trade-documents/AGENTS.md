# 贸易单据模块协作规则

- 只修改 `features/trade-documents/` 内的实现、样例、说明和模块内验证材料。
- 需要宿主或装箱能力时，通过 `docs/interfaces/` 的公开契约，不读取或修改其他模块内部文件。
- 保留每个提取字段的来源证据和确认状态；缺失或不确定值必须提示用户，不得静默猜测重量、尺寸、数量或金额。
- 样例只使用用户确认可用的文件，优先脱敏；不直接复制 `真实数据/` 内容。
- 模板和字段映射的变更需说明适用单据类型、输入字段、输出字段及未覆盖情况。

## 单据界面小改动的协作偏好

以下是用户确认的局部偏好，仅用于本项目已有单据界面的按钮、弹窗、候选选择等小范围调整（含位于 `application/web/` 的单据前端），不扩展到其他模块或架构调整。

- 需求明确后直接实现，不重复要求设计确认，不额外编写规格或实施计划；用户看过最小实现后，在同一份代码上完善。
- 默认流程：一次集中定位 → 实现 → 定向测试 → 稳定后一次浏览器验收 → 简短交付。复用上下文中未变化的规则、代码和检查结果，按函数片段读取，输出失败摘要。
- 默认不启动额外审查代理，不另建演示工程；用户明确要求或实际问题证明有必要时再使用。不因通用技能的固定流程增加这些步骤。
- 保留必要验证；失败或新增改动只重验受影响范围。浏览器集中验证修改的关键交互，截图只留关键状态，不反复识别整批文件或重复验收未变化的页面。
- 只有影响实现结果的需求歧义、范围明显扩大或需要用户决定的不可逆操作才询问，并说明具体原因；其余合理实现选择自主推进。节省额度不代表跳过正确性检查。
