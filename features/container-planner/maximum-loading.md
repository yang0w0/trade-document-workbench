# 最大装填修正

数量留空或为 0 时，网页原样提交给本地后端，不再把前端分层估算、90% 体积安全系数或自动减量当成需求数量。

`application/maximum_packing.py` 复用原装箱器的块构建、极点、旋转、碰撞与重心支撑检查。先生成定量货物候选，再比较联合布局，并尝试填充剩余候选位置。候选按已装定量件数、装载体积、总件数比较。多类求最大共享实际空间，不预先按比例瓜分空间。标准版搜索约 4 秒，增强版使用所选搜索时间；均保留当前最好可行结果。

结果标明停止原因：搜索时间、单次件数限制、候选位置无法继续装入。只有定量货物齐全且体积填满才标记 `optimal_full`；候选位置无法继续装入不构成全局最优证明。剩余缝隙可能小于货物可用朝向尺寸，也可能需要重新排布才能利用。

截图尺寸回归：柜体 5800×2350×2350 mm，定量货物 490×400×90 mm 共 44 件，求最大货物 200×200×400 mm。旧前端提交上限 1547 件，总数 1591，利用率 79.7%；修正后的标准搜索至少装入求最大货物 1754 件，总数 1798，利用率 90.0%，定量货物保留 44 件。该结果不宣称全局最优。

验证：`application/web_env/Scripts/python.exe -m unittest discover -s features/container-planner/tests -v`（项目根目录运行）。验证数量留空、截图回归、定量优先、禁止倒放、多类求最大、件数限制、零装载类别的 Excel 回读，并独立核对越界、重叠与支撑。

源码修改后，使用 `packaging/build-portable.ps1` 构建新版 `ContainerPlanner.exe`。构建产物须先验证启动、子进程装箱、Excel 导出和重新导入，再替换使用中的便携目录；旧目录保留为备份。便携版模板保存在 EXE 同级 `data/templates.json`。
