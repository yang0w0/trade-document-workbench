# 项目管理与文件约定

## 目录分类

| 内容 | 位置 |
|---|---|
| 项目入口、协作规则 | 根目录 `README.md`、`AGENTS.md` |
| 架构、管理规范、接口 | `docs/`、`docs/interfaces/` |
| 网页壳、全局导航与本地服务 | `application/web/`、`application/server/` |
| 独立业务功能 | `features/<feature-name>/` |
| 跨模块稳定契约 | `shared/contracts/` |
| 确实被多个模块复用的基础代码 | `shared/common/` |
| 功能内验证材料 | 对应模块的 `tests/` |
| 跨模块和便携包验收 | 根目录 `tests/` |
| 构建配置与依赖锁定 | `packaging/` |
| 可分发便携包 | 现有 `发布包/` |
| 本地实际业务资料 | 现有 `真实数据/` |
| 装箱输入、分析与记录 | 现有 `测试数据/`、`测试工具/`、`测试记录/` |

目标目录只在有对应内容时创建；不要用空的 `frontend/`、`backend/` 或 `common/` 目录预占位置。

## 命名规则

- 新增源码目录、接口文档 ID 使用简洁英文 kebab-case，例如 `trade-documents`、`document-export.v1`。
- 保留现有中文业务资料目录名，避免与任务无关的重命名或搬移。
- 文件名描述内容和用途；避免 `misc`、`new`、`final2` 等含义不清的名字。
- 日期格式使用 `YYYY-MM-DD`。接口在文档和机器可读契约中标明版本；变更兼容性时递增版本。
- 面向使用者的操作说明可以中文编写；代码和接口字段使用一致的英文标识符。

## 功能所有权与协作

1. 先读根 `AGENTS.md`，再只读目标模块的 README、`AGENTS.md` 和其公开接口。
2. 功能实现、模块内文档和验证材料只放在该功能目录。应用启动、全局导航和模块装配属于 `web-app/`。
3. 不为调用另一功能而阅读或修改其内部文件；向契约所有者提出缺失能力，并在本模块实现契约适配。
4. 跨模块变更范围限于公开接口、被授权的适配层及其集成验证。接口变化先更新契约，再更新调用方。
5. `shared/` 只放多个模块确实使用的稳定契约/通用能力，不放单一功能代码。
6. 每次交付说明所属模块、改动文件、接口变化、验证方式及仍未确认的内容。

## 样例和敏感资料

单据样例按 `samples/input/`、`samples/templates/`、`samples/expected/` 分类。样例文件须由用户提供并确认可用于样例，优先脱敏；不复制 `真实数据/` 的客户资料到测试目录、源码示例或发布包。无法提供真实模板时，用字段清单或合成样例描述结构。

## 发布约定

发布包必须包含运行网页所需的程序、依赖、静态资源和模板。新电脑上应能解压并双击 `ContainerPlanner.exe` 进入网页，不依赖用户安装编程环境。网页应用依赖和启动入口见 `application/requirements-server.txt` 与 `application/run_web_app.bat`。新网页应用的便携打包仍需独立建立和确认，旧发布物不能代替该构建流程。
