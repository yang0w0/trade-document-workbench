# 网页载体与功能模块接口

**Owner:** `web-app/`  
**Status:** `proposed`  
**Consumers:** `features/container-planner/`、`features/trade-documents/`

## 用途

网页载体提供统一导航和模块装配。两个业务模块分别向载体声明自己的可见入口和调用能力；载体不读取模块内部页面、算法或业务状态。

## 建议的模块描述

每个模块需要提供以下逻辑信息。网页应用当前在 `application/web/` 内使用模块导航装配两个并列功能区，API 由 `application/server/main.py` 提供。

| 字段 | 含义 |
|---|---|
| `moduleId` | 稳定且唯一的模块 ID，例如 `container-planner` |
| `displayName` | 网页导航展示名 |
| `route` | 模块在本地网页内的入口路径 |
| `owner` | 维护模块的目录 |
| `contractRefs` | 模块使用或提供的公开接口 ID |
| `capabilities` | 可选能力声明，不能替代实际接口定义 |

## 交互边界

- 载体负责模块发现/登记、导航、共享文件选择与下载入口，以及与本地服务的连接。
- 模块负责自己的页面和领域行为，并使用公开契约暴露能力。
- 模块之间不通过访问彼此内部页面状态来共享数据。
- 若实现需要启动/关闭钩子、鉴权、配置或共享状态，应先通过接口变更记录需求和生命周期，再实现。

## 错误约定

载体应能区分模块未注册、启动失败和模块业务错误；模块业务错误由模块提供可显示的简短消息及可选字段级详情。错误代码集合待实现时确定，不能在本草案中声称已存在。

## 兼容与验证

接口 ID 采用 `<owner>.<resource>.v<major>`。兼容性破坏需要新主版本并协调所有调用方。标记 `verified` 前，需检查新模块可被发现、导航进入、正常返回载体，且模块失败不会使另一个模块不可用。
