# 集装箱装箱接口

**Owner:** `features/container-planner/`  
**Contract ID:** `container-planner.plan.v1`  
**Status:** `proposed`  
**Consumers:** `web-app/`、确认货物信息后的 `features/trade-documents/`

## 用途

把明确的柜型与货物规格交给装箱模块，返回位置方案和未装入项目。单据模块只传递用户确认的字段；装箱模块不解析合同、PI 或其他贸易单据。

## 请求概念

- `container`: 长、宽、高，单位米；可以使用已知柜型预设。
- `items[]`: 稳定货物 ID、名称、长宽高（米）、数量、单件重量（kg）、类型及朝向约束。
- 当前本地 HTTP 实现为 `POST /api/jobs` 的 `rows[]`；尺寸有效且 `n=0` 表示求最大，前端不得替换成保守估算件数。定量货物优先保留。最大装填响应额外提供按有效行对齐的 `maxFlags`、`stats.fixed_complete`、`stats.max_search_stop`；`optimal_full` 仅在定量齐全且体积填满时为真。搜索结果是可行下界，不代表全局最优。
- `orientationConstraints`: 例如“禁止倒放”。此约束只在源数据或用户明确确认时设置。
- `options`: 计算模式及相关搜索参数，由装箱模块定义。

## 响应概念

- `summary`: 已装/总件数、空间利用率、用时和是否全部装入。
- `placements[]`: 货物 ID、实例/数量、坐标、朝向和尺寸，按装箱模块已验证的数据约定表示。
- `unplaced[]`: 未装入货物 ID、数量和可提供的原因。
- `warnings[]`: 输入缺失、约束不支持或结果需人工复核等提示。

## 错误

至少区分输入字段/单位无效、柜型或货物为空、约束冲突、计算超时和内部计算失败。错误消息不得伪装成“全部装入”或有效摆放结果。

## 当前实现核验事项

此契约是建议边界，不代表当前 exe 已提供该 API。源码/API 盘点时需要确认现有计算入口、字段名、尺寸单位、返回结构、算法模式及取消/超时行为；然后由模块所有者修订本文件并标为 `verified`。单据功能不得为适配未验证字段而读取 `ContainerPlanner.exe` 内部数据。

## 兼容与验证

主版本表示请求/响应结构不兼容变化。标为 `verified` 前，至少用有效输入、错误单位、禁止倒放和部分未装入场景核对实现与接口说明；测试数据使用非敏感样例。
